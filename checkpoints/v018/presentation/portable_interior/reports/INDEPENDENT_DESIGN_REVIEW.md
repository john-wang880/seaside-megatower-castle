# Independent safety review — opt-in portable video runner

Frozen historical interior recipe51files must remain byte-identical. This is a NEW workflow, not a reinterpretation of the verified MP4. No Blender run, install, encode, model edit or Git action in this review.

## Required invariants / concrete risks
1. **Authoritative OS lock, not process enumeration.** Windows msvcrt byte-range locking or LockFileEx on a retained open handle; POSIX flock on supported platforms. Ensure a stable byte exists and seek to the same byte on Windows. Never unlink/recreate a lock inode or bypass a lock based on timestamp/PID. Process listing can advise about unrelated Blender jobs but cannot establish exclusive output ownership. Scope is one shared output path; two different outputs are not globally serialized by this lock. A separate global render-resource lock is needed only if promising that stronger property.
2. **Recheck after lock.** Existing runner checks run_identity and approval before acquiring lock; a new implementation must re-read identity/source/code/approval/pilot evidence under the held lock before any mutation or skip. Check again at each subprocess boundary if code/source can change during a long run; fail closed rather than mix identities. Worker must receive/check expected worker/plan/source hashes, not merely report whichever code it happens to execute.
3. **Explicit guards survive python -O.** Use exceptions for source/identity/approval/path/lock/frame checks. Assertions may be fixture conveniences, not authorization gates. A portable frame validator that inherits assert-only checks must reject optimized execution or replace those guards.
4. **New identity covers ALL executable helpers.** Source, recipe, motion, worker, runner, validator and portability/locking helpers. Record Blender executable/version and chosen quality/thread options; do not silently adopt different options when resuming. Optional metrics are data, not a reason to broaden quality equality. Fresh pilot gate bound to exact25indices+pilot_complete hash+full identity; old approval cannot authorize new code. Historical completed frames/video are historical only unless a separately explicit import policy is designed and audited; default no imports/relabeling.
5. **Path containment before mutation.** Resolve existing ancestors/junctions/symlinks; forbid output equal to source or an ancestor containing source, and forbid source/code/archive/approval inside output tree. Do not accept source==output merely because is_dir differs. Inherited old guard `source not in out.parents` does not reject `out in source.parents`; explicitly test both relevant relations. Reject ambiguous pre-existing foreign output roots or identity-free frame trees. All attempts/quarantine/logs/temp manifests/final video must stay under one owned output root. Paths passed as argv lists, no shell interpolation; Windows Unicode/spaces must work. Network-share locking semantics are unverified: restrict support to local filesystem or explicitly decline guarantees.
6. **Atomic progress / interruption.** Unique temporary files in same directory, flush/fsync before replace where supported, replacement only after successful validation. Preserve failed attempts; never treat exit0 as enough. Invalid existing frame moves to unique quarantine only under lock. Failed rename/Windows sharing violation is a clean stop/retry, not delete-first fallback. Atomic rename is not a substitute for a lock. Completion receipt only after all intended indices validate again.
7. **Runtime portability.** resource/sched_getaffinity/proc are optional and imported conditionally; metadata uses explicit null/unavailable rather than fabricated zeros. No hard-coded9-CPU requirement. Missing ffmpeg/ffprobe permits frame rendering if configured, but encoding must fail clearly and preserve frames. Never auto-install. Blender still --disable-autoexec; never save source.
8. **Resume and video.** Skip only valid same-index/source/code/settings/PNG hash and decoded-image evidence. One source PNG per actual frame; no fabricated interpolation. Reuse encoded video only when video hash and current frame-set receipt hash match; independently decode/count/PTS/size/fps/duration/noaudio. Lossy repeated decoded frames can be legitimate subpixel-motion quantization; preserve corresponding original PNG provenance and report, not mislabel as fabrication.

## Decisive negative/control tests (Linux real + Windows adapter mocks, not native Windows certification)
- Two real simultaneous runner processes contend for same output lock; loser performs no mutation. Keep stale-looking lockfile after owner exits: next process acquires same OS lock normally, without deletion. Inject access denied/sharing errors and prove no bypass.
- Inject identity change between preflight and lock acquisition: fail before writes. Change helper/source/plan after one frame: stop next frame, no mixed completion receipt.
- `python -O` wrong-source/old-approval/wrong-worker fixture must still reject. New helper hash invalidates old approval.
- Wrong pilot indices/receipt hash/approved=false/missing pilot frame, valid old-generation frame in new root: reject.
- Source equals output; output contains source/archive/approval; symlink/junction resolves outside owned root; foreign output with frame files but no identity; spaces/Unicode paths. No deletion, rename or write outside owned root.
- Worker exits0 but missing/wrong index/PNG/metadata/camera/settings/hash: preserve attempt and fail; truncated PNG; wrong file extension; source mutated in worker; stale receipt.
- Interrupted temp-write/rename/quarantine and existing destination: no valid frame overwritten, clean recovery rechecks content. Denied quarantine rename stops rather than purges.
- Missing resource/affinity/proc; Windows lock adapter acquisition/release exceptions; ffmpeg unavailable; wrong video count/fps/PTS/audio. Unsupported platform/filesystem exits clearly.

## Review boundary
Linux tests and mocks can demonstrate program logic and POSIX lock behavior, not actual Windows Blender/NTFS/junction/share behavior. Label native Windows execution untested until a real run. Do not claim current historical video was generated or revalidated by this new code. Concrete source/code preservation and pilot visual review remain distinct from portability claims.
