# v008 · 东桥头入岩台阶与真实入口

阶段成果，不是最终成品。基于 v007，用 Blender 5.2.3 LTS 实际建模、重开和 Cycles 渲染。

## 本轮解决的问题

桥面原本约 z=26.97，而东侧岩岸平台约 z=28.8；桥的轴线还被实心、外倾的廊道基座封住。只叠加台阶会把台阶藏进墙里，因此本轮同时处理真实入口与承托。

- 保留原廊道基座，在副本中开出沿桥轴线的真实拱口，原倒角修饰器保留。正面的 15 块拱券石跟随实际墙面倾斜，不浮空。
- 11 级宽缓石阶，总升高 2.0、单级约 0.1818、净宽 4.6，连接至外侧平平台；增加低石栏和分块踏面。
- 承托实体逐段埋入实际岩岸，不是悬空薄片。
- 对通路范围内 11 个岩片构件做局部开挖；选中岩片原本埋在地下的开放底面先闭合，再执行布尔操作。其他岩片和地形不变。
- 原始 80 网格、64 材质及所有原对象变换保留；新增构件与替代对象单独分组，源对象隐藏保留。相机、光照、世界与曝光不变。

## 实际验证

- 工程重开、原始数据保留、同源重复构建通过。
- 33 处实际网格射线采样：踏面高于地形、基础埋入岩岸、上方 2.1 单位净空无阻挡。
- 新建筑网格闭合、零非流形边、正体积；未改岩片保留原拓扑，不把整个岩片集合误报成闭合体。
- v007 西桥头 9 条净空射线回归通过。
- 同机位前后 Cycles CPU 实渲，无生成式补画或照明修改。

这些是局部离散检查，不是整座城堡的导航网格验证，也不是现实建筑工程认证。西侧草坡到入口的台阶、东入口之后的内院路线仍需继续优化。

## 恢复与重建

下载/克隆整个仓库（需包含根目录 model_chunks/），然后运行：

```
python checkpoints/v008/restore_checkpoint.py
```

恢复到 checkpoints/v008/restored/castle_v008.blend。脚本使用标准 Python，校验每个内容寻址块和完整模型 SHA-256，不需要安装压缩库。模型原始压缩字节不重新编码，恢复结果与验证模型逐字节相同；使用 Blender 5.2.3 LTS 或兼容版本，关闭自动执行后打开。

MANIFEST.json 按原始顺序引用 model_chunks/ 中的 SHA-256 文件。未变化的数据块可在后续版本复用，减少重复备份载荷。恢复时不会覆盖内容不同的已有模型；可用 --output 指定另一个输出文件。

旧 ZIP 分片恢复格式仍可在提交 4ff652e7100ac265d8f12a070b350fb37bb41868 中使用。

重建脚本 scripts/refine_v008.py 需要 v007 源模型，拒绝覆盖输入或在已加工的 v008 上重复叠加。v007 可从 Git 提交 4678deec80b81e20ffbc396c632ca881ca5b6740 恢复。
