# v011 — 保留原始数据的性能整理

本版没有改建筑、材质或灯光。仅清理4份无依赖、已隐藏的**中间林木副本**（V007与V009各两份），完整原始森林和最新可见V010森林均保留。旧中间状态可从v010提交 `38f9d594ea390e03b35a87921e6d0e7f19d232cc` 恢复。

## 实测结果
- 压缩工程54,307,405→32,691,218字节，缩小**39.80%**。
- 102个保留网格与86个可见求值网格，经完整拓扑、属性、材质索引、法线及相关状态哈希比较一致；变换、材质图、灯光、相机、世界均未变化。
- 同机位东入口中性诊断图与全景原照明图，均900×650；和v010逐像素比较**100%相同，最大通道差0**。
- 本机3次交错、独立进程、热缓存加载测量：峰值RSS中位数535,656→495,372KiB（下降7.52%）。这是本机观察，含启动内存；不是通用内存/速度保证，也没有宣称渲染加速。

报告见 `reports/equivalence.json`、`benchmark.json`、`east_comparison.json`、`hero_comparison.json`。依赖审计见 `inventory.json` 与 `recommendation.json`。清理前检查单用户、无父子/约束/修改器/动画/驱动依赖，不对其他源对象做全局清除。

## 恢复
下载/克隆整个仓库（包含 `model_chunks`），运行：
```
python checkpoints/v011/restore_checkpoint.py
```
得到 `checkpoints/v011/restored/castle_v011.blend`，Blender5.2.3LTS验证。模型SHA256：`95b9de7c661817f7cb00dfb531724355d49a33983a6b02b0305959ac4d06c2fe`。

重建本次整理：从历史v010恢复模型，运行 `scripts/consolidate_v011.py --output <新文件.blend> --report <报告.json>`。历史建模脚本仍应配合其历史来源检查点使用，勿用新文件替代其特定旧输入。
