# S101：城堡厨房的连续石作工作区

基线为已完整回读的 S100（GitHub `77751d15617ee6c135ffd98f84543d9720d65a79`）。用户重新授权继续迭代。本版不是城堡全部完工，也不以小道具充当一次版本。

在保留餐桌、家庭和守卫交通、储藏入口、原梁柱及世界设置的前提下，重整约 9 米长的南侧厨房工作区：厚石拱灶龛、连续备餐台和储架，以及有实体底壁和实际开口的洗盆。69 个精确列明的旧厨具隐藏归档，未删除历史。

## 功能边界
灶龛是真实空间，但没有已验证通向室外的烟道；上方仍有既存屋面、露台和塔壳。模型没有火焰，不将冷灶宣称为安全可用的炉火。洗盆没有实际供排水。独立送膳楼梯尚未完成，送膳仍共用旧梯。模型不是已运行的游戏交互或工程施工图。

初版洗盆底板和边缘与原承重柱相交，被独立验收拦下。修订只让新石作绕开旧柱，不删改柱或扩大施工范围。拒绝证据保留，最终结果以绑定最终模型哈希的验收和实际渲染为准。

## 增量备份
S100 原始完整归档保持不动。从 S101 起，Blender 先输出未压缩原始文件，再用固定 zstd 1.5.7 单线程、level 3、无 checksum 参数封装为交付模型。原始文件和封装文件都记录 SHA-256。差分基于前一模型解压后的原始数据，避免对已有压缩文件盲目做巨大的补丁。

每次备份保存父提交、最近完整基准、链深、原始和封装哈希、补丁及各分片哈希、编码工具版本与哈希，并保存脚本、验收和图像。回读必须从 GitHub 取回数据，在新目录恢复原始模型并重新封装，验证交付文件的精确哈希，不只检查上传成功。实际篡改一字节、缺片、错误父模型的负测试必须拒绝且不产出冒充成功的模型。

最多连续 8 个增量，之后建立新的完整基准；旧分支和归档永远不因建立新基准而删除。原始数据超过已测 512 MiB 窗口时，不默默扩大解码范围，先使用完整备份或建立经过实测的新配置。跨平台若编码工具不同，只能在明确验证原始文件的恢复方式下使用该有效 Blender 原始文件，不能冒称容器字节一致。

本版仍是单一模型。未来可把地形、外堡、每层室内等拆为有独立资源哈希的模块，但须先验证链接资产、加载路径和整堡显示，不能仅把文件拆开就声称模块化完成。
